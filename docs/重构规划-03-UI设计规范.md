# 重构规划 03 · UI 与交互规范

> 目标：像一个克制、可靠的 Windows 系统工具，而不是产品官网、数据仪表盘或 AI 模板。
> 实现：WPF + WPF-UI；本文件是验收约束，不是情绪描述。

## 1. 信息架构

默认窗口只围绕一件事：**查看当前位置的菜单项，并快速添加 CLI。**

```text
┌────────────────────────────────────────────────────────────────────┐
│ 右键菜单管理                                                — □ × │
├────────────────────────────────────────────────────────────────────┤
│ 位置 [文件夹空白处 ▾]  [搜索名称或命令……]  [添加 CLI] [＋ ▾] [刷新] │
├────────────────────────────────────────────────────────────────────┤
│ 图标  在 Claude Code 中打开                         开启      ⋯   │
│       claude.exe · Windows Terminal · 当前用户                    │
│ ────────────────────────────────────────────────────────────────── │
│ 图标  在 Codex 中打开                              开启      ⋯   │
│       codex.cmd · Windows Terminal · 当前用户                     │
│ ────────────────────────────────────────────────────────────────── │
│ 图标  Open Git Bash here                           只读      ⋯   │
│       HKLM · command                                              │
│                                                                    │
├────────────────────────────────────────────────────────────────────┤
│ 12 项 · 9 个可编辑                 已更新 · 撤销       [高级项] [⚙] │
└────────────────────────────────────────────────────────────────────┘
                                            ┌───────────────────────┐
                                            │ Inspector（按需滑出） │
                                            │ 显示名                │
                                            │ 可执行文件            │
                                            │ 参数                  │
                                            │ 终端                  │
                                            │ 命令预览（只读）      │
                                            │        取消  保存     │
                                            └───────────────────────┘
```

### 为什么不用固定四栏导航

CLI 核心场景只有“文件夹空白处”。顶部为位置区域：P0 只有一个 provider 时显示普通文字“文件夹空白处”，不放无意义的单选项 ComboBox；P1 启用第二个位置后原位升级为 ComboBox。设置与经典菜单放在右下角设置入口，不占用主任务导航。

## 2. 页面与动作

### 主列表
- 默认仅显示当前 `ContextLocation` 的有效项。
- 筛选：全部 / 受管 / 现有 / 只读；“显示高级项”控制隐藏、条件、遮蔽与未知结构。
- 主动作“添加 CLI”打开 CLI-first Inspector。
- `＋` 下拉中的次动作：添加普通应用、添加原始命令、从注册表导入（P1）。
- 单击行选中；双击或 Enter 打开 Inspector。
- 每行始终显示启停状态；编辑、删除等动作放在行尾 `⋯`，不堆一排图标按钮。
- 可迁移的 HKLM 简单项（用户自己用管理员 regedit 添加的项）不标成死的“只读”：行尾 `⋯` 提供“迁移到当前用户”，标注需要一次管理员确认；真正只读的只有复杂/系统项。

### Inspector
同一个右侧面板承担新建、查看与编辑，不用多层模态框。

受管 CLI 简单模式：
- 工具名称/显示名。
- 可执行文件（发现结果或浏览选择）。
- 终端：自动、Windows Terminal、经典控制台。
- CLI 退出后保持窗口。
- 图标预览。
- 只读的最终启动说明，不展示易误导的手工 shell 模板。

高级区折叠后才显示：
- 参数数组编辑器。
- 注册表位置、键 ID、schema 版本。
- 对现有简单项显示 raw command。
- “转换为受管 CLI”。

只读项 Inspector 显示来源、类型和不可编辑原因，不出现伪可用的保存按钮。

可迁移 HKLM 项的 Inspector 显示字段均为只读，但提供主动作“迁移到当前用户”：
- 说明文案陈述事实：“此项位于系统范围（HKLM）。迁移后可直接编辑，需要一次管理员确认以删除原项。”
- UAC 被拒绝时如实显示“已复制到当前用户，原系统项仍存在（已被遮蔽）”，提供重试；不显示伪成功。

旧版遗留项（如 `RightMenu.codex`）的 Inspector 显示“由旧版本创建”提示与“升级为受管项”动作，升级前预览新旧命令对比。

### 设置
使用 WPF-UI `ContentDialog` 或独立设置页，包含：
- 默认终端、主题。
- 实验性经典菜单开关及 Windows 版本。
- 操作历史与恢复。
- 导出注册表、修复受管项安装路径。

操作历史不需要独立主导航页；默认只保留最近 50 次，按需展开。

## 3. 视觉规范

### 基础原则
- 使用 WPF-UI 的 Fluent 控件、系统主题和系统强调色。
- 不自绘整套按钮/开关/滚动条/标题栏。
- Mica 仅用于窗口背景；内容区保持足够不透明度和对比度。
- 一屏至少显示 10–12 个菜单项。

### Token（`Themes/Tokens.xaml`）

| 类型 | 允许值 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 |
| 圆角 | 控件 4；面板/对话框 8 |
| 字号 | 12 辅助；13 正文；14 分区；20 对话框标题 |
| 行高 | 16 / 18 / 20 / 28，与字号一一对应 |
| 列表行 | 44–48，高度全局一致 |
| 图标 | 行图标 20；功能图标 16 |
| 分隔线 | 1px 系统中性描边 |
| 阴影 | 只用于 Dialog/Flyout；列表和面板无阴影 |

颜色：
- 使用 WPF-UI/系统主题资源，不在 View XAML 里散落品牌色。
- 强调色只用于主要按钮、开启状态、选中指示和焦点环。
- 危险色只用于最终删除动作与错误文本。
- HKLM、只读、Shift 等信息用中性文字或轮廓标记，不用彩色 badge 墙。

字体：
- `Segoe UI Variable Text`，中文回退 `Microsoft YaHei UI`。
- 命令/路径用 `Cascadia Mono`，回退 `Consolas`。
- 图标用 WPF-UI SymbolIcon/Segoe Fluent Icons，不用 Emoji。

## 4. 明确禁止的“AI 味”

- 紫蓝渐变、霓虹、彩色阴影、玻璃卡片堆叠。
- 大标题 + 灰色产品介绍副标题。
- “智能扫描”“一键搞定”“太棒了”等营销文案。
- 三四个大数字统计卡片。
- 每个区域都套圆角边框、每行都像独立卡片。
- Emoji 图标、彩色首字母圆块。
- 首屏空状态插画和多段说明。
- 每个表单字段下都放一段解释；只在有风险或歧义处说明。
- 自定义标题栏抢占系统窗口行为；优先使用 WPF-UI FluentWindow 的稳定实现。
- 隐藏真实注册表项来制造“干净列表”；应该分组和折叠，而不是过滤丢失。

## 5. 交互规范

| 场景 | 要求 |
|---|---|
| 搜索 | `Ctrl+F` 聚焦；按显示名、可执行路径、raw command、键名过滤；≤100ms |
| 新建 | `Ctrl+N` 打开“添加 CLI” |
| 导航 | 上下键移动；Enter 编辑；Space 启停；Delete 进入确认；Esc 关闭面板 |
| 刷新 | F5；保留当前筛选和选中项 |
| 加载 | 扫描 <300ms 不显示 loading；超过后只在状态栏显示进度 |
| 保存 | 就地刷新；状态栏显示结果和“撤销”，不弹成功框 |
| 错误 | Snackbar 显示可执行说明，并可复制详细信息 |
| 删除 | ContentDialog；显示名称、来源、完整键路径；默认焦点“取消” |
| HKLM/复杂项 | 复杂/系统项控件只读并明确原因；用户简单项提供“迁移到当前用户”，UAC 仅在用户点击该动作时触发一次；不提供常驻“以管理员重启” |
| 并发冲突 | 检测到注册表在编辑期间变化，要求刷新或明确覆盖，不静默写入 |
| Explorer 重启 | 只在经典菜单开关后或确有缓存问题时提供；操作前确认会关闭文件管理器窗口 |

## 6. CLI 添加体验

点击“添加 CLI”后：
1. 首屏列出已发现的 Claude Code、Codex、Gemini、Kiro、Antigravity、OpenCode；每项显示状态与完整路径。
2. 点击一个工具即预填显示名、路径、图标和终端。
3. 同名多路径必须选择；未发现时提供“浏览选择”，不显示伪成功状态。
4. 保存前执行只读验证：文件存在、扩展名支持、目标键不冲突、安装路径稳定性提示。
5. 可选“测试启动”：用用户选择的测试目录运行，但必须明确会启动真实 CLI；不能在扫描阶段自动执行。

批量添加是 P1，只有单项闭环可靠后实现。

## 7. 多位置扩展体验

- P0 的位置区域显示不可交互的“文件夹空白处”；P1 完成第二个 provider 后在同一位置替换为 ComboBox。
- P1 每完成并验收一个 provider 才把相应位置加入列表。
- “文件类型”使用二级选择器（扩展名 + ProgID），不能把数百个 ProgID 全部塞入主列表。
- 切换位置时列表、计数、搜索范围和新增目标同步变化；Inspector 中始终显示实际注册表路径。
- COM/现代扩展若进入 P2，放在“高级项 > 扩展处理器”独立分组，不能与静态命令共用编辑表单。

## 8. 无障碍与系统适配

- 所有图标按钮有 `AutomationProperties.Name`。
- 焦点可见，Tab 顺序与视觉顺序一致。
- 文本对比度至少 4.5:1；支持高对比度模式。
- 跟随系统浅/深主题与强调色，可在设置里覆盖主题。
- 100%、150%、200% DPI 下无模糊、裁切和横向滚动。
- 最小窗口 `880×560`；默认 `1040×720`。
- Inspector 打开后焦点进入首个字段；关闭后归还原列表行。
- 屏幕阅读器能读出名称、来源、状态、可编辑性和只读原因。

## 9. UI 验收清单

- [ ] 首屏没有产品介绍段落、统计卡片、渐变和 Emoji。
- [ ] 默认位置是“文件夹空白处”，最多两步添加一个已发现 CLI。
- [ ] 一屏能看到至少 10 行。
- [ ] 键盘可完成搜索、新建、编辑、启停、删除和撤销。
- [ ] HKCU/HKLM、有效/遮蔽、简单/复杂项能明确区分；用户自己的 HKLM 简单项（如 OpenCode、Cursor）显示为“可迁移”而非死的只读。
- [ ] 高级项不会被扫描器丢弃，默认折叠后可展开。
- [ ] 浅色、深色、高对比度和 200% DPI 验证通过。
- [ ] 最小窗口无重叠与横向滚动。
- [ ] 经典菜单明确标记实验性，Explorer 重启前有确认。
- [ ] 后续位置加入后不改变主界面信息架构。
